## Source supplement: audit the publishing receipt against actual files

The author's [xaiwind/x-article-publisher](https://github.com/xaiwind/x-article-publisher/blob/6cd2f1b752afe966c00bb803c1a1c5eb7a1085d4/README.md) is now available, pinned to `6cd2f1b`. ### Apply five source-backed steps

1. **Pin the tool and inputs.** Record repository, commit, Markdown path, title and assets. The entry point is [auto-publish.js](https://github.com/xaiwind/x-article-publisher/blob/6cd2f1b752afe966c00bb803c1a1c5eb7a1085d4/auto-publish.js#L22-L51), with dependencies in [package.json](https://github.com/xaiwind/x-article-publisher/blob/6cd2f1b752afe966c00bb803c1a1c5eb7a1085d4/package.json). Verify actual Articles access against [X's official guidance](https://help.x.com/en/using-x/articles).
2. **Resolve image paths first.** [payload.js](https://github.com/xaiwind/x-article-publisher/blob/6cd2f1b752afe966c00bb803c1a1c5eb7a1085d4/payload.js#L77-L141) checks local paths and Obsidian attachments; this entry point rejects HTTP remote images. Eligible PNG/JPEG files may use macOS `sips` compression; other platforms skip it. Do not assume every asset was compressed.
3. **Define the browser-session scope.** The user signs in during a headed first run before considering `--headless`. `--profile` selects a separate session directory. The code may close an instance sharing that profile and clear lock files, so identify affected windows and execution scope first. This entry point has not been run here.
4. **Inspect individual receipt fields.** [xpage.js](https://github.com/xaiwind/x-article-publisher/blob/6cd2f1b752afe966c00bb803c1a1c5eb7a1085d4/xpage.js#L725-L854) counts `imgOk`, `imgFail` and `atomicFail`; failed images, code or tables may degrade to text. The function can still return `ok: true`, which does not establish complete images or formatting.
5. **Reopen the draft for acceptance.** The [entry-point ending](https://github.com/xaiwind/x-article-publisher/blob/6cd2f1b752afe966c00bb803c1a1c5eb7a1085d4/auto-publish.js#L189-L220) waits for autosave, cleans markers and returns a draft URL, without a separate server-content readback. Reopen it and check title, cover, image order/count, format degradation and leftover markers before a human publication decision.

A **synthetic receipt** with `ok=true`, `summary.imgOk=8` and `summary.imgFail=2` means a partial draft needing repairs. This explains the recording's missing-image state; it does not prove this site repaired those two images.
