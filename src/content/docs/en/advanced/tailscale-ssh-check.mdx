## Scenario and input

Prepare client, target, os_user, ssh_mode, allowed_scope and revoke_method without placing private keys in ordinary notes.

## 1. Confirm target and scope

Record device ownership and the intended directory before approving client installation or access-policy changes.

## 2. Authorize the devices

Authenticate through the current Tailscale flow and verify device identities instead of copying another environment's parameters.

## 3. Choose the SSH mode

Traditional SSH over the tailnet and Tailscale-managed SSH are different configurations. The latter needs network and SSH authorization.

## 4. Verify host and directory read-only

Check the host identity prompt, then use read-only commands such as whoami and pwd to confirm the actual user and directory.

## 5. Document recovery and revocation

Document failure handling, device revocation and an alternate authorized recovery path without exposing SSH publicly.

## A synthetic acceptance fixture

Two separate checks: the network reaches the target, and the intended identity can access the intended OS user. Network reachability alone does not enable SSH.
