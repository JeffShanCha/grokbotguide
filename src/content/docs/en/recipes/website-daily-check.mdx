**Every morning the Bot opens your analytics, deployment history, GitHub repository and live pages, confirms yesterday’s content is live and traffic looks normal, and writes a Markdown report.**

## What you get

<RecipeShot slug="website-daily-check" />

## When to use it

- You run several sites and checking each dashboard takes time
- You worry a failed deploy or a broken page goes unnoticed

## Before you start

- Analytics (Plausible, GA4 and so on) that the Bot can sign in to in its browser, ideally with a read-only member account.
- A sign-in for your hosting platform, such as Cloudflare, also read-only if possible.
- The GitHub plugin.

## Steps

1. Give the Bot your site URL and dashboard links; run it once.
2. Confirm the report format, especially how it marks unverified items.
3. Create a routine for 08:00 daily.

## Prompt

Replace the parts in angle brackets with your own.

<CopyTemplate id="website-daily-check">

```text
Every day at 8:00 (America/New_York), check <https://your-site>:
1. Deploys: open the hosting platform’s deployment history, confirm the latest deploy succeeded and note the time
2. Content: confirm yesterday’s post opens and appears in the sitemap and RSS feed
3. Traffic: compare yesterday’s visits with the same day last week in analytics; flag changes over 30%
4. Repo: list unmerged PRs and failed Actions on GitHub
Save a Markdown report to /workspace/reports/<date>.md and send me a summary in chat.
If any item will not open or needs verification, mark it "unverified" with the reason; never fill in from old data.
```

</CopyTemplate>

## Approvals and permissions

- Read-only: no deploys, no setting changes, no merges.
- Use the smallest possible dashboard permissions.



## Notes and pitfalls

- This is Flavio Copes’s "Blog Pulse" routine. When his analytics were locked, the Bot marked that section unverified instead of filling it in from older data; put that rule in your prompt.
- Analytics or hosting dashboards may block cloud IPs; you will need to take over for verification.
- Keep reports in /workspace; files elsewhere may be lost when the computer resets.
