## 场景与输入

合成目标：每周交一份内容周报，尚无稳定的采集流程。

## 1. 收敛一个结果

让用户选择一个近期交付目标，并明确成功样例、时间和不做的范围。

## 2. 先写角色草案

每个角色只有一份主要产物，列职责、输入、停止点和接手人；角色名不代替输出标准。

## 3. 检查教学模板

读取模板包含什么以及是否附带外部应用或自动化；未读到的描述不直接当成可运行配置。

## 4. 按任务核对应用

列出必要连接器、账号和只读验证；作者推荐的插件名称不等于已安装、可用或已授权。

## 5. 确认后再扩角色

先手动跑通一份周报，再决定保存模板或增加专员；创建、群聊和定时都与规划分开确认。

## 一份合成验收样例

roster.csv：role、input、deliverable、reviewer、trigger。起步只设资料整理员和本人审阅，不默认同时创建出海站与视频团队。

## 视频补充：给发布统筹一份可核对的 X 长文草稿

59 秒的录屏不是建团队教学，而是团队中“发布统筹”岗位的一次工作演示：把本地 Markdown 和图片送入 X Articles 草稿。它补出一项正文与配图未描述的流程。

| 时间点 | 画面证据 | 交付含义 |
| --- | --- | --- |
| 00:00–00:14 | Bot 报告使用 `x-article-publisher`，用户提供本地 Markdown 路径 | 先明确输入文章和配图；技能已安装是画面中的自述 |
| 00:14–00:25 | 出现本机命令授权，文件复制有失败后重试 | 命令授权和素材复制是独立环节，需要分别核对 |
| 00:25–00:43 | 用户进入 Bot 电脑浏览器完成 X 登录与验证，再交还控制 | 网站会话需要本人处理；安装连接器不能代替这次登录 |
| 00:43–00:58 | Bot 返回草稿链接、标题、封面和图片结果：10 张成功 8 张 | 草稿已有，但缺 2 张图；画面没有正式发布完成的证据 |

### 把这个岗位写成五步交付

1. **交素材清单。** 给出 Markdown 的确切路径、标题、封面和应有图片清单，约定本轮只生成草稿。
2. **核对执行条件。** 原演示使用第三方技能和浏览器自动化；本轮没有取得它的仓库地址或审查脚本，不能仅凭技能名称补造安装命令。已有可信实现时，再核对它将运行的命令、位置和文件范围。
3. **检查素材是否齐全。** 文件拷贝失败要报缺项；“已复制 10 张”不能替代编辑器中的上传结果。
4. **由本人完成登录。** 按电脑接管卡片登录并处理验证，再交还给 Bot；这是[官方接管流程](https://cursor.com/docs/grok-bot/work)，本文不复述画面里的账号或验证码。
5. **按草稿清单验收。** 回执包含草稿链接、标题、封面、应有与实际图片数、缺图名称和未完成项。像录屏的 8/10，应先补图并重新预览；最终发布另作明确决定。
