**会用 GitHub 就提 PR，不会就填 [投稿表单](/zh/community/submit/)。** 两条路最后都进同一个仓库，内容采用 CC BY-SA 4.0，代码采用 MIT。

## 方式一：GitHub PR

1. Fork 仓库，复制 `templates/article.md`（角色卡用 `templates/bot.md`，模板用 `templates/template.md`）。
2. 放到 `src/content/docs/zh/<栏目>/<英文-slug>.md`。
3. 提 PR。可以只写中文，维护者会补英文版。
4. CI 会自动检查 frontmatter、构建和链接。
5. 合并后自动上线，文章顶部显示你的署名，页面底部有「编辑此页」。

## 方式二：投稿表单

不想碰 Git？[在这里投稿](/zh/community/submit/)。表单会自动生成一个 GitHub Issue，维护者整理后发布，同样署你的名字。

## 内容分级

| 标签 | 含义 | 要求 |
| --- | --- | --- |
| 整理自官方文档 | 来自 docs.x.ai 等官方信息 | 每条事实都要链接到官方原文 |
| 整理自社区分享 | 来自他人公开分享的实测（博客、视频、X 帖子） | 每篇都要链接原文并署名；本站复现后升级为「社区亲测」 |
| 社区亲测 | 作者亲自跑过 | 写明测试日期、订阅档位、用到的应用 |
| 观点 / 评测 | 个人判断 | 明确标注为个人观点 |

## 审核标准

- 验证状态是否如实：亲自跑通的标「社区亲测」，写明测试日期和订阅档位；没跑过的标「整理自官方文档」或「整理自社区分享」，并附来源
- 是否写清权限设置和用量感受
- 截图里有没有邮箱、客户名、Token 等敏感信息
- 是否和已有内容重复
- 参考了别人的内容，是否实质改写并在 `sources` 里列出

维护者目标是 72 小时内给出结论。

## 复验

每篇文章都有 `last_verified` 日期。超过 60 天会被标记为「待复验」，任何人都可以按文中步骤重跑一遍，更新日期后提 PR。

## 贡献者激励

- 文章顶部署名，链接到你的 GitHub
- 首页贡献者墙（把自己加到 `src/data/contributors.yaml`）
- 合并第一篇投稿即可免费加入知识星球的 Grok Bot 专栏
