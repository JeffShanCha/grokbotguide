## 场景与输入

合成目标：仅供自己访问一个测试页面；不处理真实客户请求。

## 1. 收集只读资源信息

查看操作系统、CPU 与 cgroup 限制、内存、磁盘挂载和可用工具；数字写采集时间，不推成所有套餐配置。

## 2. 明确服务边界

写清仅本人访问还是公网访问，是否需要流式、WebSocket、持久磁盘和登录；每种协议单独验收。

## 3. 核对隧道方案

先选择私网或受保护的测试入口，核对当前官方服务限制；临时隧道可访问不代表有稳定性保证。

## 4. 测试生命周期

记录客户端关闭、云电脑空闲、软件更新和电脑重建分别影响什么；自启动脚本不能代替实际恢复测试。

## 5. 按证据决定用途

能满足测试就保留为实验环境；关键服务另评估可用性、备份和正式托管，不用持续保活猜测替代 SLA。

## 一份合成验收样例

audit.csv：cpu_limit、memory_limit、disk_mount、network_path、sleep_test、restore_test。两个目录位于同一磁盘时不把容量相加。

## 验收与复核

每项资源与协议有实际证据或待测标记；没有承诺全天在线、固定规格或数据永不丢失。

分开列通过、失败、未测试与依据；合成数据和真实结果分别标注。
