## 准备：先用一份你能核对的素材

需要一个可用的 Grok Bot，以及能阅读附件、创建文件的现有 Bot。练习样例不需要连接 X，也不需要托管账号或新的 API Key。

1. 下载本页的 `source.csv`，通过聊天输入框的附件入口上传给 Bot。
2. 核对文件里是 8 条合成短文，列名为 `id,date,text,url`。演示数据的 `url` 留空，不伪装成真实帖子。
3. 后续所有文件放在同一个项目目录。Bot 返回的绝对路径以实际结果为准，不要把自己 Mac 的路径当成云电脑路径。

先发送这段开场指令。它会让 Bot 只确认素材和工作范围，避免一口气开始后面的所有步骤。

<PortraitPrompt stage="setup" />

### 想用四个 Bot 时，怎样分工

可以先让同一个 Bot 按顺序切换岗位。需要长期分工时，再在桌面侧栏选择 **New → Create new Bot**，在 **Edit Profile** 中配置名称和职责。按下表分别配置即可。

| 岗位 | 可写进描述的职责 | 本轮应交付 |
| --- | --- | --- |
| 素材编辑 | 校验输入、保留出处，报告缺失和重复；不做个人推断 | `source.csv` |
| 证据编辑 | 只提出能回到素材核对的观察，保留不确定性 | `claims.json` |
| 内容设计 | 把确认过的观察组织成读者能理解的一页内容 | `site-brief.md` |
| 网页制作 | 根据已确认文件实现网页，并报告实际检查结果 | `site/index.html` |

把四个 Bot 放进群聊时，在 **New chat** 选择它们。每一步先用 `@` 菜单选中负责的 Bot，再粘贴下方指令；输入一串普通的 `@名字` 不一定完成真正的指派。同账号的 Bot 可以使用共用文件，但不同岗位并不代表账号权限隔离。

**交接时一次只 `@` 下一位。** 本次真实群聊修订中，同时提到内容设计和网页制作后，网页先于设计说明完成更新。最终文件核对一致，但顺序没有严格串行。需要固定顺序时，先等设计说明交付并核对，再用一条新消息单独指派网页制作，不要只在同一条消息里要求“两位按顺序来”。

## 第一步：校验素材，而不是急着评价你

发送给素材编辑。完成后检查数量、日期、正文和缺失说明；样例应当仍然是 8 条。

<PortraitPrompt stage="intake" />

**通过标准：** `source.csv` 能打开，每条有稳定的 id，正文与输入一致，没有凭空补出的原文链接。下一步引用 id，比让 Bot 反复转述原文更容易核对。

<PortraitPrompt stage="live" />

</details>

## 第二步：建立主题与证据的对应关系

发送给证据编辑。这里寻找的是这些文字里出现的主题和表达习惯，不是给人打人格分数。

<PortraitPrompt stage="evidence" />

打开 `claims.json`，抽查一个主题，再核对它引用的两三条素材。问自己：这些文字真的支持这句话吗？一句玩笑是否被放大成长期观点？没有足够依据时，删掉观察比加一个好听的标签更有用。

本次样例中的一个结果是「自动化先手动、再放权」，依据来自 `demo-02`、`demo-04` 和 `demo-05`。它描述的是样本里的表达，不代表真实用户的完整人格。

## 第三步：先确认内容，再做视觉

发送给内容设计。先回答网站给谁看、要让读者记住什么，再决定卡片顺序和排版。

<PortraitPrompt stage="brief" />

**通过标准：** 读者能从导语理解这页是什么；每个主题有证据入口；没有未经你提供的履历、头衔、联系方式或成绩。可以参考[这次生成的设计说明](/demos/portrait/site-brief.txt)，但你自己的介绍应由自己的素材决定。

## 第四步：生成一个能独立打开的网页

发送给网页制作。本练习使用单文件 HTML，目的是先拿到能检查的结果，不必一开始就配置框架和部署服务。

<PortraitPrompt stage="build" />

拿到 `index.html` 附件后，可以下载并在自己的浏览器打开。Bot 给出的云端 `localhost` 地址不能直接当成你 Mac 上的本地地址；如果预览链接打不开，先让它提供 HTML 附件，不要把一个无法访问的路径当成交付完成。

演示里，二丫头交回了 HTML 和其他中间文件。本站检查后把它放到本地样例入口，并重新拍摄了本页截图。

## 第五步：核对证据、手机布局与真实交付

把检查指令发给当前负责页面的 Bot。

<PortraitPrompt stage="review" />

自己也做三件事：点一个证据 id；切到手机宽度；读一遍所有描述，删掉你不认可的推断。截图只能说明某个视口，完整内容仍要在可打开的网页里核对。

### 想发布时，再单独确认

本教程做到可打开的网页和检查结果。决定公开前，再核对内容、托管账号、仓库、构建方式和公开范围，并明确授权发布。Vercel 或 Cloudflare Pages 是可选托管方式；本次演示没有连接它们，也没有验证部署。

## 常见问题

**没有 X 插件，能做吗？** 可以，先用本页 CSV 或自己有权使用的短文。缺少采集能力只影响拿素材，不影响后面的证据、内容和网页制作。

**只有一个 Bot，能做吗？** 可以，合成练习就是二丫头串行处理四个岗位。真实 X 加测又复用了四个现有 Bot 验证群聊交接；两种方式都能交付文件，不必为了练习新建四个 Bot。

**为什么合成样例里没有头像和真实姓名？** 样例没有真人身份信息，Bot 不应补造。真实 X 加测也没有使用作者头像，避免把第三方观察做成本人主页。制作自己的页面时，可以另外提供你决定公开的姓名和有权使用的头像。

**可以直接使用蓝哥 AI 的原图和原提示词吗？** 本页没有采用这些素材。参考作品保留在文末；本站提供的是独立编写的提示词和自己演示产生的页面截图。
