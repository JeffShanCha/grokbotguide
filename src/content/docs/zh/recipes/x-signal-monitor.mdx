把采集窗口、累计数据、增量阈值和通知状态分开，先离线比较两次样本，再讨论定时与存档。

## 场景与输入

合成快照：P1 在 08:00 为 4,000 次浏览，09:00 为 10,000；演示阈值为每小时增加 5,000。

## 1. 固定观察范围

明确账号名单、公开来源、时间窗口与白天/夜间规则；不可用数据先报告，不承诺抓到所有帖子。

## 2. 建立带时间快照

保存 post_id、observed_at、views 和读取状态，按原帖 ID 去重；相同时间的快照不能当成两个采样点。

## 3. 写清阈值口径

区分累计值、增量与单位时间增长；本文样本用差值除以小时数，缺基线时不触发增长告警。

## 4. 验证通知去重

同一帖子和规则只发一次，记录 pending、sent、unknown；发送结果不明先查回执，不立刻重发。

## 5. 单独确认存档与定时

先交本地样本结果；GitHub 文件范围、是否公开、提交和推送、Routine 频率分别确认。外部模型也有自身计费条件。

## 一份合成验收样例

P1 的一小时增量为 6,000，触发一次。只有 10,000 累计值而无前次快照时，不能推算小时增速。alert_key 使用 post_id 与规则版本。
